SQaLe

A large realistic dataset to empower small specialised text-to-SQL models

Abstract

Frontier language models in agentic pipelines lead text-to-SQL benchmarks, at a high inference cost. Small specialised models would avoid that cost, but training them needs data that reflects the scale, semantics and structure of real databases.

SQaLe is a semi-synthetic text-to-SQL dataset built on 9,259 real-world schemas from SchemaPile. Our generation pipeline extends each schema, fills it with synthetic rows, generates questions and answers them with an agent, and validates every stage by execution. The result is 1,408,056 natural-language questions paired with SQL, over schemas far larger than in any existing dataset. We train Qwen3.5-2B on SQaLe with GRPO alone, and its execution accuracy on the SQaLe test set rises from 24.0% to 54.7%. The model learns to explore the database: it finds the relevant tables in large schemas and reads the values its answer needs, which training on existing datasets elicits far less.

Pipeline

    
How SQaLe is built.

    
Five stages turn a SchemaPile schema into question and SQL pairs. Every stage is validated by execution.

  

  

    
    
      
  1. 
        1
        
    Schema collection and extension
    
        
    We start from SchemaPile's real-world schemas, mined from permissively licensed GitHub repositories. A tool-using agent annotates each source repository with a domain description. LLM-generated tables extend each schema and keep its naming conventions, normalisation level and foreign-key style.
    
        
    14,597 source repositories annotated
    
      
    2. 
      
  2. 
        2
        
    Value synthesis
    
        
    Tables are filled in foreign-key dependency order. For each table the LLM writes a Python function from its DDL, its original rows, the allowed foreign-key values and the domain description. Fact and junction tables get more rows and a skewed key distribution. Every table is checked for primary-key uniqueness and referential integrity.
    
        
    95.2% of tables populated · 95.1% of foreign-key cells valid after repair

  3. 
        3
        
    Question generation
    
        
    We sample a connected subgraph along foreign keys, with sample rows, and ask for questions that need every table. Questions come at three difficulty levels (simple, moderate, hard), and every literal is grounded in the data.
    
        
    Subgraphs of up to 20 tables

  4. 
        4
        
    Style variation
    
        
    Each question is rewritten into seven styles: casual, structured, requirements list, short and high level, short and ambiguous, spelling and grammar mistakes, and evidence supported. All eight phrasings share the gold SQL.
    
        
    8 phrasings · 1 gold SQL

  5. 
        5
        
    Agentic answering and judging
    
        
    An agent explores the live database with list_tables, describe_table, sample_rows, distinct_values and run_query, and commits with submit_sql. Execution errors go back to the agent. An LLM judge checks the result against the question and sends rejected queries back for a rewrite.
    
        
    94.5% of judge-accepted queries are aligned with the question (225 judge calls on 158 BIRD dev questions; 86.2% agreement with human labels, κ = 0.68)

Comparison

    
How SQaLe compares.

    
23.4% of SQaLe queries are nested, against 7.7% in BIRD. 40% of joining queries chain multiple joins (BIRD 26%). 3.1% of queries touch five or more tables, up to 20. No BIRD or EHRSQL query touches more than four.

Results

    
Trained on SQaLe, Qwen3.5-2B rises from 24.0% to 54.7%.

    
MSQaLe is Qwen3.5-2B trained with GRPO on SQaLe. MBIRD and MSynSQL are the same model trained with the same recipe on BIRD train and on SynSQL-2.5M. Only the data differs.

  


  

    

      

        
Recipe

        
GRPO directly from the base checkpoint. Base model, environment, tools, reward, steps, batch size and evaluation are identical across the three runs. No distilled traces, no teacher, no test-time scaffolding.

      

      

        
Environment

        
The schema is withheld. The model explores the database through tools: list_tables, describe_table, sample_rows, distinct_values, run_query, foreign_keys and join_path.

      

      

        
Reward

        
Tiered: a correct result ranks above a query that executes, which ranks above one that parses. Partial credit never ranks a wrong query above a correct one.

Findings

    
What SQaLe teaches.

  


  

    

      
Schema size

      
Accuracy falls as the schema grows. MSQaLe leads at every size.

      
At full schema size MSQaLe inspects 71.3% of the gold tables, against 56.5% for MBIRD and 60.2% for MSynSQL. BIRD and SynSQL training schemas have a median of 5 and 10 tables, so models trained on them never have to search.

Populated tables

      
MSQaLe reads the values its answer needs.

      
Before submitting, MSQaLe has seen 75% of the string literals its answer depends on, against 45% for MSynSQL, 36% for MBIRD and 25% for the untrained model. SynSQL's tables hold a median of 2 rows; SQaLe's hold 69.

Domains

      
The lead over MBIRD is larger outside BIRD's domains.

      
On SQaLe test questions whose schemas lie outside BIRD's domains, MSQaLe leads MBIRD by 9.9 points (46.4 vs 36.5). Inside BIRD's domains it leads by 2.8 points (39.3 vs 36.5).

      
The sample covers 108 schemas, too few to call the difference between the two gaps significant.
