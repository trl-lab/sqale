    Why SQaLe

    Frontier language models in agentic pipelines lead text-to-SQL benchmarks, at a high inference cost. Small specialised models would avoid that cost, but training them needs data that reflects the scale, semantics and structure of real databases.

    SQaLe is a semi-synthetic text-to-SQL dataset built on 9,259 real-world schemas from SchemaPile. Our generation pipeline extends each schema, fills it with synthetic rows, generates questions and answers them with an agent, and validates every stage by execution. The result is 1,408,056 natural-language questions paired with SQL, over schemas far larger than in any existing dataset.

    We train Qwen3.5-2B on SQaLe with GRPO alone, and its execution accuracy on the SQaLe test set rises from 24.0% to 54.7%. The model learns to explore the database. It finds the relevant tables in large schemas and reads the values its answer needs, which training on existing datasets elicits far less.

    How it is built
    
      
    
        
    Five stages, each validated by execution.
    
      
    
    
    
    
    
      

      
      
        
    1. 
          01
          
      Schema collection and extension
      
          
      We start from SchemaPile's real-world schemas, taken from permissively licensed GitHub repositories. A tool-using agent annotates each of the 14,597 source repositories with a domain description. Each schema is extended with LLM-generated tables that keep its naming conventions, normalisation level and foreign-key style.
      
        
      2. 
        
    2. 
          02
          
      Value synthesis
      
          
      Tables are filled in foreign-key dependency order, each by a Python function the LLM writes from the table's DDL, its original rows, the allowed foreign-key values and the domain description. Fact and junction tables get more rows and a skewed key distribution. Every table is checked for primary-key uniqueness and referential integrity.
      
          PK and FK check, repair
        
      3. 
        
    3. 
          03
          
      Question generation
      
          
      We sample a connected subgraph along foreign keys (up to 20 tables) with sample rows, and ask for questions that need every table. There are three difficulty levels (simple, moderate, hard), and every literal is grounded in the data.
      
        
      4. 
        
    4. 
          04
          
      Style variation
      
          
      Each question is rewritten into seven styles: casual, structured, requirements list, short and high level, short and ambiguous, spelling and grammar mistakes, evidence supported. All eight phrasings share the gold SQL.
      
        
      5. 
        
    5. 
          05
          
      Agentic answering and judging
      
          
      An agent explores the live database with list_tables, describe_table, sample_rows, distinct_values and run_query, and commits with submit_sql. Execution errors go back to the agent. An LLM judge checks the result against the question and sends rejected queries back for a rewrite. 94.5% of the queries the judge accepts are aligned with the question (225 judge calls on 158 BIRD dev questions; 86.2% agreement with human labels, κ = 0.68).

    Results
    
    
    
      
    Trained on SQaLe, a 2B model reaches 54.7% on the SQaLe test set.
    
      
    
        
    We train Qwen3.5-2B with GRPO directly from the base checkpoint three times: on SQaLe, on SynSQL-2.5M and on BIRD train. Base model, environment, tools, reward, steps, batch size and evaluation are identical. There are no distilled traces, no teacher and no test-time scaffolding. MSQaLe is Qwen3.5-2B trained with GRPO on SQaLe; MBIRD and MSynSQL are the same recipe on BIRD and on SynSQL.
    
        
    The schema is withheld. The model explores the database through tools (list_tables, describe_table, sample_rows, distinct_values, run_query, foreign_keys and join_path). The reward is tiered, with a correct result above a query that executes, above one that parses, above nothing. Partial credit never ranks a wrong query above a correct one.

    What SQaLe teaches
    
    
    
      
    A model trained on SQaLe searches the schema and reads the data.
    

      
    
        
    
          
    Schema size
    
          
    Accuracy falls for every model as the schema grows, and MSQaLe leads at every size. At full schema size MSQaLe inspects 71.3% of the gold tables, against 56.5% for MBIRD and 60.2% for MSynSQL.
    
          
    BIRD and SynSQL training schemas have a median of 5 and 10 tables, so models trained on them never have to search.

    Domains
    
          
    On SQaLe test questions whose schemas lie outside BIRD's domains, MSQaLe leads MBIRD by 9.9 points (46.4 vs 36.5). Inside BIRD's domains the lead is 2.8 points (39.3 vs 36.5).
