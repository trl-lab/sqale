-- TL;DR

Frontier language models in agentic pipelines lead text-to-SQL benchmarks, at a high inference cost. Small specialised models would avoid that cost, but training them needs data that reflects the scale, semantics and structure of real databases.

SQaLe is a semi-synthetic text-to-SQL dataset built on 9,259 real-world schemas from SchemaPile. Our generation pipeline extends each schema, fills it with synthetic rows, generates questions and answers them with an agent, and validates every stage by execution. The result is 1,408,056 natural-language questions paired with SQL, over schemas far larger than in any existing dataset.

We train Qwen3.5-2B on SQaLe with GRPO alone, and its execution accuracy on the SQaLe test set rises from 24.0% to 54.7%. The model learns to explore the database: it finds the relevant tables in large schemas and reads the values its answer needs, which training on existing datasets elicits far less.

-- Key numbers

SELECT schemas, tables, questions, distinct_sql FROM corpus;
SELECT med_tables, med_cols, foreign_keys, synthetic_rows, med_rows FROM schema_stats;

SQaLe pairs 1,408,056 natural-language questions with 176,761 distinct SQL queries on 9,259 schemas. The median schema has 113 tables and 538 columns.

The schemas hold 1,103,669 tables, 1,196,078 foreign-key relations and 108,708,694 synthetic rows, a median of 69 rows per table. 95.2% of tables are populated, and 95.1% of foreign-key cells are valid after repair.

Train and test are split by schema, 95% and 5%.

-- How it is built

EXPLAIN SELECT * FROM sqale;
QUERY PLAN
  1. Result on sqale(pairs=1,408,056 distinct_sql=176,761)
    Output: (question, schema, sql), split by schema, train 95% / test 5%
    1. ->Agentic Answering and Judging(judge_aligned=94.5%)Stage 5
      Filter: (executes) AND (judge accepts)

      An agent explores the live database with list_tables, describe_table, sample_rows, distinct_values and run_query, and commits with submit_sql. Execution errors go back to the agent. An LLM judge checks the result against the question and sends rejected queries back for a rewrite. 94.5% of the queries the judge accepts are aligned with the question (225 judge calls on 158 BIRD dev questions; 86.2% agreement with human labels, κ = 0.68).

      1. ->Style Variation(phrasings=8)Stage 4
        Output: 7 rewrites + original, one shared gold SQL

        Each question is rewritten into seven styles: casual, structured, requirements list, short and high level, short and ambiguous, spelling and grammar mistakes, evidence supported. All eight phrasings share the gold SQL.

        1. ->Question Generation(max_tables=20 levels=3)Stage 3
          Filter: every literal grounded in the data

          A connected subgraph of up to 20 tables is sampled along foreign keys, with sample rows. The LLM is asked for questions that need every table, at three difficulty levels (simple, moderate, hard), with every literal grounded in the data.

          1. ->Value Synthesis(rows=108,708,694 populated=95.2%)Stage 2
            Filter: unique primary keys AND referential integrity

            Tables are filled in foreign-key dependency order, each by a Python function the LLM writes from the table's DDL, its original rows, the allowed foreign-key values and the domain description. Fact and junction tables get more rows and a skewed key distribution. 95.1% of foreign-key cells are valid after repair.

            1. ->Schema Collection and Extension on schemapile(schemas=9,259 repos=14,597)Stage 1
              Output: extended schema, domain description

              SchemaPile's real-world schemas come from permissively licensed GitHub repositories. A tool-using agent annotates each of the 14,597 source repositories with a domain description. Each schema is extended with LLM-generated tables that keep its naming conventions, normalisation level and foreign-key style.

EXPLAIN prints the last step at the top, so a plan reads from the bottom up. Start at schema collection, stage 1, and follow the arrows up to the release.

Every stage is validated by execution before its output moves on. The Filter line under each node names the check.

-- How it compares

SELECT dataset, schemas, med_tables, med_cols, fks, med_rows FROM corpora ORDER BY med_cols DESC;
SELECT dataset, n_sql, n_nl, pct_func, pct_where, pct_join, pct_nested, pct_agg FROM query_stats;

The median SQaLe schema has 113 tables and 538 columns. The median BIRD schema has 5 tables and 39 columns, and the median SynSQL schema 10 tables and 72 columns.

23.4% of SQaLe queries are nested (BIRD 7.7%), and 40% of joining queries chain multiple joins (BIRD 26%). 3.1% of queries touch five or more tables, up to 20. No BIRD or EHRSQL query touches more than four.

med_rows is the median number of rows per table. pct_* columns give the share of SQL queries, in %, that use functions, WHERE, joins, nesting and aggregation.

-- Results

-- Same recipe, different data

\dconfig train.*

MSQaLe is Qwen3.5-2B trained with GRPO on SQaLe. MBIRD and MSynSQL are the same model trained the same way on BIRD train and SynSQL-2.5M.

Base model, environment, tools, reward, steps, batch size and evaluation are identical. There are no distilled traces, no teacher and no test-time scaffolding.

The schema is withheld, and the model explores the database through tools. The reward ranks a correct result above a query that executes, that above a query that parses, and that above nothing. Partial credit never ranks a wrong query above a correct one.

-- Execution accuracy

SELECT model, sqale, bird, ehrsql FROM eval ORDER BY sqale DESC;

Execution accuracy in %, on 300 SQaLe test questions, BIRD and EHRSQL.

On the SQaLe test set, training on SQaLe adds 30.7 points to the base model, training on BIRD 19.7 and training on SynSQL 13.3. MSQaLe ends 3.6 points behind Qwen3.6-27B.

On BIRD, MBIRD scores 54.7 and MSQaLe 52.3. On EHRSQL the two tie at 23.7.

-- What SQaLe teaches

-- Schema size

SELECT schema_size, m_sqale, m_bird, m_synsql FROM scale_eval;

Accuracy falls for every model as the schema grows, and MSQaLe leads at every size. At full schema size it inspects 71.3% of the gold tables, against 56.5% for MBIRD and 60.2% for MSynSQL.

BIRD and SynSQL training schemas have a median of 5 and 10 tables, so models trained on them never have to search.

-- Populated tables

SELECT model, literals_seen FROM traces ORDER BY literals_seen DESC;

Before submitting, MSQaLe has seen 75% of the string literals its answer depends on. MSynSQL has seen 45%, MBIRD 36% and the untrained model 25%.

SynSQL's tables hold a median of 2 rows. SQaLe's tables hold a median of 69.

-- Domains

SELECT split, m_sqale, m_bird, m_sqale - m_bird AS gap FROM domain_eval;

NOTICE: sample of 108 schemas; too small to call the difference between the two gaps significant

On SQaLe test questions whose schemas lie outside BIRD's domains, MSQaLe leads MBIRD by 9.9 points (46.4 vs 36.5). Inside them it leads by 2.8 (39.3 vs 36.5).

The sample of 108 schemas is too small to call the difference between the two gaps significant.
